# Guides

**Location**: `docs/guides/`

Documents that explain how to use something the project has built, written for a person outside the build: an end user, a customer's staff, or the operator adapting the text into help copy.

**The test is what a document is, not which spec caused it to exist.** A guide explains how to use the product; a spec defines what to build. A guide produced by a spec's task list still lives here, not in `docs/features/done/`, because a spec number is a build-order position a guide has no use for.

## Naming

Descriptive, no number and no prefix. The folder already states what these are.
