# Initialise the application

A repository created from this template is full of placeholders (`{{APP_NAME}}`, `{{APP_SLUG}}`, `{{SKILL_PREFIX}}` and the rest; the list is `PLACEHOLDERS` in `tools/init/placeholders.py`). This skill collects the values and hands them to `tools/init/init_app.py`, which does all of the file work deterministically. **Never edit placeholders by hand or with ad hoc search and replace**: the script checks that nothing unknown is left before it writes a byte, renames paths, and writes the marker. Doing it by hand skips all three.

## Rules

- **Runs once.** If `.laravel-app-initialised.json` exists, stop and say so. Nothing re-runs init, and the script refuses too.
- **Secrets never enter this conversation.** Do not ask the operator to type a password, never read `laravel/.env`, and never print a value from it. The passwords are either generated by the script straight into `laravel/.env`, or left blank for the operator to fill in themselves.
- **No commit, no push, no stack.** The result is one uncommitted diff for the operator to review. Do not run `make up` or anything else that starts containers.

## 1. Establish the facts

```bash
python3 tools/init/init_app.py --detect
```

- `initialised: true`: stop. Report that this repository was initialised and point at `docs/initialisation.md`.
- `dirty: true`: stop. List `git status --short` and ask the operator to commit or stash first, so init is a single reviewable diff.
- `env_exists: true`: tell the operator the existing `laravel/.env` will be moved aside to `laravel/.env.pre-init-<timestamp>`, not deleted.
- `github_owner` and `github_repo` come from `remote.origin.url`. If either is empty there is no GitHub remote; ask for both.

## 2. Ask the questions

Use `AskUserQuestion`, at most four questions per call, putting the suggested value from `--detect` first with "(Recommended)". The operator types anything else through "Other". Ask in two calls:

**First call**
1. **App name**: the display name. Offer the repository name in title case.
2. **Slug**: offer `suggested.app_slug`. Explain that it becomes the database (`<slug>`), the users `<slug>_rw` and `<slug>_ro`, the Compose project and the image names, and must be 2 to 24 lower-case letters and digits, starting with a letter.
3. **Skill prefix**: offer `suggested.skill_prefix`. The project's own skills become `/<prefix>-merge`, `/<prefix>-sync-local` and so on. 2 to 8 lower-case letters and digits, and not `speckit`.
4. **Port suffix**: offer `100` and one random value from 101 to 999. The local ports become 8NNN (app), 5NNN (Vite), 33NNN (MySQL) and 63NNN (Redis). Different apps on one machine need different suffixes.

**Second call**
1. **GitHub repository**: offer `<github_owner>/<github_repo>` from git, as detected.
2. **Local HTTPS domain**: offer `suggested.local_domain` (`<slug>.test`).
3. **Production domain**: offer `suggested.production_domain` and say it is only a placeholder until there is a real one.
4. **Database passwords**: "Generate random passwords (Recommended)": three 32-character passwords for the `_rw` user, the `_ro` user and MySQL root, written to `laravel/.env` only. Or "I will set them myself": they are left blank, and `make up` will not work until they are filled in.

Then ask in plain text for a **one-line description**, of at most 200 characters, for the README and `CLAUDE.md`.

Neither the app name nor the description may contain `"`, `\`, `$`, a backtick or a brace. The script rejects them, so say so before they are typed.

## 3. Confirm, dry run, apply

Show every answer in one table. Write them to a file **outside the repository**, so the working tree stays clean for the script's check:

```bash
ANSWERS="$(mktemp -t init-answers).json"
cat > "$ANSWERS" <<'JSON'
{
  "app_name": "...",
  "app_slug": "...",
  "app_description": "...",
  "skill_prefix": "...",
  "github_owner": "...",
  "github_repo": "...",
  "port_suffix": "...",
  "local_domain": "...",
  "production_domain": "...",
  "generate_passwords": true
}
JSON
python3 tools/init/init_app.py --answers "$ANSWERS" --dry-run
```

A `FAIL` names every bad answer. Re-ask only those, then dry-run again. If it reports placeholders that would remain, stop: a template file uses one that `PLACEHOLDERS` does not list, which is a template bug and not something to patch around.

On a clean dry run, ask the operator once to go ahead, then:

```bash
python3 tools/init/init_app.py --answers "$ANSWERS"
rm -f "$ANSWERS"
```

## 4. Verify

```bash
python3 tools/init/check_placeholders.py
for d in tools/docs-guard tools/po-check tools/roadmap tools/init; do (cd "$d" && python3 -m unittest -q); done
git status --short | head -40
```

`check_placeholders.py` must report none left. The skill directories are now `.claude/skills/<prefix>-*`. **Claude Code loads skills at session start**, so the renamed skills appear as `/<prefix>-*` only in a new session.

## Output

The summary the script printed (the same text as `docs/initialisation.md`), then:

```
Placeholders   none left
Tests          docs-guard, po-check, roadmap, init: OK
Changed        <N> files, <M> paths renamed, laravel/.env written (not tracked)

The operator's actions
- Review the diff, then commit it (the summary gives the command)
- Start a new Claude Code session so the /<prefix>-* skills load
- make up, then make doctor
```

## Out of scope

- Committing, pushing, or opening a PR.
- Starting the stack, or any database command.
- Changing a value after init: that is an ordinary edit through the normal process.
