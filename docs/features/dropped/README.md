# Features: dropped

**Location**: `docs/features/dropped/`

Work that was specified or seeded and then abandoned. Kept because the reasoning is the valuable part: a dropped spec answers "why did we not do that", a question that comes back and is expensive to reconstruct from memory.

## Dropped is not deferred

Deferred work goes to `docs/features/backlog/` and keeps a future. Dropped work has no future in its current form. If the idea comes back it comes back as a new capture, informed by the document here, not as a resurrection of it.

## Every document here must open with a status note

State, at the top and before the original title, that the document is superseded or dropped, on what date, and where the decision now lives, with an explicit instruction not to build against it. Without that line the file reads as live specification, and the whole risk of keeping abandoned work is that somebody builds against it.

## Numbers

A number in this folder is **not** released. Check this folder as part of any number allocation sweep.
